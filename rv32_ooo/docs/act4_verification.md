# ACT4-derived architectural tests: results, inventory, and gap

**All 135 delivered ACT4-derived self-checking ELFs pass with zero failures,
conversion rejections, or timeouts.**
The source inventory contains 136 generated programs. One JAL program cannot link within the
fixed 64 KiB RAM and remains an explicit unexecuted coverage gap. The user chose to retain
64 KiB. These selected, adapted architectural tests are not a certification claim.

The final report is `reports/act4_execution_results.json`, with per-program logs in
`reports/act4_execution/`. It records the exact 135-file manifest inventory and current
core/runner hashes; the complete selected-source inventory and one gap are accounted for below.

The local 755,125 RTL-regression checks are separate evidence. So are the synthetic loader,
harness, and batch-runner expectations described below. A successful Sail/reference build,
ELF conversion, or harness selftest is not itself a passing DUT architectural program.

## Preserve the tests while splitting their files

The initial upstream selection has 54 source programs. The wrapper uses the ordinary upstream
splitter with an in-process 128-case target instead of the default 1,000, yielding 136 source
programs. It does not edit upstream source files or substitute a different random seed.
Comparison records preserve all **13,441 testcase/debug labels, 23,240 operand literal
directives, and 12,258 complete pre-split chunks** in the source inventory. These preservation
counts describe generated sources; they do not assert that the unbuilt JAL program executed.

New file boundaries change code/data addresses, per-file canaries, and pointer-reset code.
Expected signatures were therefore regenerated by the actual Sail reference model. Three copied
environment alignment sites change `.option rvc` to `.option norvc` so this non-C platform uses
32-bit NOP alignment. Splitting also required correcting only the pre-first-chunk pointer
initialization prefixes in `M-div-03.S`, `M-mulhsu-03.S`, and `M-mulhu-03.S`, using the preceding
logical chunk's end state. Original chunk instruction lists, operands, and self-checks remain
unchanged. The manifest records all old/new prefixes, locations, hashes, and comparison results.

## The retained 64 KiB layout gap

`rv32i/I/I-jal-00.S` contains one preserved indivisible upstream chunk. Its tested offsets reach
only **±8192**; the obstacle is cumulative alignment padding across the test's case layout.
`.text.rvtest` ends at `0x24000`, and the complete signature image reaches `0x279c0`, about
158.4 KiB. The fixed RAM ends at `0x10000`, so the linker correctly rejects the image.

This is not an inherent JAL target-range requirement, a passing test, or a demonstrated RTL
failure. The user explicitly chose to keep 64 KiB and document the gap. The source and rejection
log are retained. No offsets were shortened, checks removed, or RAM enlarged. Resolving this
case would require a separately reviewed layout/splitting adaptation that preserves every case,
label, target distance, and check. Thus 135 built programs plus one unexecuted gap account for
all 136 selected generated sources.

## Reproduce generation and reference compilation

Inside the prepared environment, use the pinned checkout at `/act4` and mount this project at
`/project`. From `/act4`, run:

```sh
uv run --frozen --no-dev python /project/verification/act4/generate_small_tests.py
uv run --frozen --no-dev act /project/verification/act4/test_config.yaml \
  --test-dir /project/build/act4_small/tests \
  --workdir /project/build/act4_small \
  --extensions I,M,Zicsr,Zifencei --keep-going
```

The generator writes `/project/build/act4_small/tests` and its generation manifest. The second
command produces the final ELFs under `build/act4_small/custom-rv32im/elfs`; it also reports the
retained JAL link failure, so the overall build is incomplete. Do not interpret that command as
an all-green suite build. The reference stage runs `.sig.elf` intermediates on Sail and embeds
expected signatures into final ELFs. Only final self-checking ELFs are DUT inputs; pointing a
batch run at the entire build tree would also discover unsuitable intermediates.

The delivered `verification/act4/elfs` and exact manifest already contain the 135 successfully
built final programs, so rerunning those DUT tests requires no RISC-V compiler or container.
Regeneration must preserve the pinned configuration/adaptations and retain a new build manifest.

## Run the delivered programs

From the delivered project root, with Python 3, Icarus Verilog, and vvp:

```sh
python3 scripts/run_act4_suite.py \
  --elf-dir verification/act4/elfs \
  --manifest verification/act4/manifest.json --jobs 8
```

Optional controls include `--output-dir`, `--max-cycles`, `--wall-timeout`, `--data-latency`,
`--predict 0|1`, and `--tohost`. Defaults use mailbox `0x1000fff0`, one million simulated cycles,
120 seconds per simulation, data latency two, and prediction enabled. Eight independent
simulations share one compiled harness; `--jobs` does not alter the processor's issue width.

The runner discovers every `.elf` recursively, with no test-name filter, and checks exact
manifest filename sets and SHA-256 values. Missing/unlisted/changed ELFs are errors. Every input
receives a passed, failed, conversion_failed, or timeout result. An empty inventory cannot pass.
It creates a timestamped run directory with conversion/simulation logs and `results.json`, and
updates the selected output directory's latest report. Source/ELF hashes and tool versions are
retained. A matching manifest proves inventory integrity, not certification.

For a single ELF and optional waveform:

```sh
python3 scripts/run_act4.py --elf verification/act4/elfs/rv32i/I/I-add-00.elf \
  --vcd build/act4_add.vcd
```

The loader accepts integer-ABI ELF32 little-endian RISC-V `ET_EXEC` at entry zero, rejects
malformed/overlapping/out-of-RAM segments, and zero-fills BSS. The real-core harness uses shared
instruction/data RAM and strobed requests. PASS requires a mailbox store of 1, its successful
response, and matching architectural retirement. A different nonzero value fails; zero does
not finish a test. A speculative result or request alone cannot terminate simulation.

## Separate infrastructure evidence and interpretation

```sh
python3 scripts/test_act4_elf_to_mem.py
python3 scripts/run_act4.py --selftest
```

The recorded infrastructure reports have **10 loader tests, seven harness expected outcomes,
and 49 batch-runner expectations**, all matched. They test local synthetic inputs, including
intentional FAIL/timeout/rejection, parallel accounting, manifest checks, and empty-suite
rejection. They are not added to the number of architectural ELFs that passed.

A program-reported PASS means that self-checking input succeeded on this core. The harness does
not independently compare every retirement with another ISA simulator. The documented layout
gap, selected nonprivileged scope, adaptations, and unresolved signoff work remain visible even
when every executable in the delivered directory passes. No exhaustive formal proof, silicon
validation, Vivado fit/timing/DRC result, or architectural certification is claimed.
