# Accepted-scope completion audit

The active two-issue processor has passing functional evidence for the accepted RTL scope. All 15 local groups pass **755,125 checks**, and **all 135 delivered ACT4-derived ELFs pass** with zero failed, conversion-rejected or timed-out inputs. The user-approved JAL layout gap and implementation/signoff limits remain explicit. This audit checks artifacts and recorded evidence; it is not certification or a guarantee about untested behavior.

The audit recomputed source/input/log hashes and inspected the actual RTL/testbenches rather than treating the plan as implementation evidence. Detailed machine-readable results are in [completion_audit.json](../reports/completion_audit.json).

## What was accepted

The final target is a two-issue RV32IM_Zicsr_Zifencei M-mode OoO processor with five logical sections, 64 physical registers, a 16-entry ROB, eight issue entries, four ordered memory entries, a 64-entry tagged BTB and 128 two-bit PHT counters. The user removed firmware and FPGA/IP integration, retained the Vivado/part/clock specifications, waived checkpoint waits, extended verification time, and accepted the fixed-64-KiB JAL test-layout gap. Classical in-order interstage forwarding/register requirements were superseded by the accepted OoO queues, tags and completion bypass.

## Accepted gaps and practical limits

- **Accepted JAL architectural-test layout gap**: I-jal-00.S is retained but cannot link in 64 KiB: cumulative alignment yields image end 0x279c0. Tested offsets are within +/-8192. No cases were counted as passed; directed JAL/JALR programs pass.
- **Architectural certification and privileged profiles**: ACT4-derived final ELF success covers the selected I/M/Zicsr/Zifencei configuration, not all possible programs or a certification profile. Privileged suites, optional CSR/WARL equivalence and Sm certification were not run.
- **Formal/signoff/silicon**: No exhaustive formal proof, synthesis/latch report, FPGA resource fit, STA, DRC, CDC/RDC, power, silicon validation or advance guarantee is established by simulation.
- **Performance**: Two is the maximum width, not a guaranteed IPC. Memory is head-only and one outstanding, divider is iterative, prediction recovery waits for retirement, and serialized operations cause stalls.
- **External system contracts**: Supply synchronous IRQ levels, common clock/reset, one-stage held native RAM output, coherent shared little-endian storage/collision holds and AXI routing/endpoints. Reset endpoints consistently; old pre-reset responses must not alias new work.
- **Deliberately absent architecture**: No caches/DDR/MMU/OS boot, speculative load replay/store forwarding, global-history/loop predictor/RAS, U/S modes/PMP, FPU/vector/atomic/compressed ISA, multicore coherence or external debug module.
- **FPGA and firmware delivery**: No AMD IP Integrator project, board wrapper, UART/GPIO IP, clock/reset IP, pin constraints, implementation/bitstream flow or application firmware/runtime/driver package; retain target specification only.

The selected ACT4 programs are self-checking executables built with a configured Sail reference. The DUT harness requires a completed, retired PASS mailbox store. It does not compare each retired instruction against Sail during that DUT run. Local full-core reference comparisons and architectural self-checking programs provide complementary evidence.

## Reproduce the observations

```sh
python3 scripts/run_checks.py --block all
python3 scripts/run_checks.py --block 15 --waves
python3 scripts/test_act4_elf_to_mem.py
python3 scripts/run_act4.py --selftest
python3 scripts/run_act4_suite.py --elf-dir verification/act4/elfs --manifest verification/act4/manifest.json --jobs 8 --max-cycles 1000000 --data-latency 2 --predict 1 --wall-timeout 180
python3 scripts/build_guide.py
```

Use Python 3, Icarus Verilog and vvp for local simulation. Delivered ELFs avoid a compiler installation for rerunning the DUT tests. Rebuilding ACT4 inputs needs the documented pinned upstream/compiler/Sail environment. The target note specifies Vivado 2026.1 Linux, Artix-7 `xc7a35tcpg236-1`, Basys 3 reference, 100 MHz input and a **50 MHz target**; these are specifications, not achieved FPGA results.
